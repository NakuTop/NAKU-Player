# Naku NAS 账号同步协议 v1

## 当前实现

NAKU Player 2.5.0 macOS 登录 NAS 后，默认将 Naku 电影、剧集、动漫的观看历史和收藏同步到当前账号的个人目录。“设置 → 同步与备份”提供统一同步状态、开关、立即同步及完整片库备份入口；NAS 页面提供跳转入口。资料变更后延迟5秒同步，每60秒检查其他设备的变更。网络不可用时本地继续使用；退出并忘记账号后暂停同步。当前片库已绑定其他账号时暂停，避免跨账号合并。

同步目标为 `<个人目录>/NakuPlayer/sync-v1/<account>/`。账号身份 `account = lowercase hex SHA256(UTF8(serial + "|" + username))`，与 NAS 播放资源引用保持一致。账号密码与会话 token 不进入同步文件，保留本机钥匙串的既有登录方式。下载媒体、下载任务、播放器设置不在本协议范围。

这里存放的是 Naku 的独立数据，不会修改绿联影视中心自身的收藏或观看记录。未来 iOS、Android、Windows 等客户端需要实现本协议及对应的 NAS 登录和文件传输，登录同一账号后才能共享这些信息。当前未完成真实手机客户端间的验收。

## 云端文件

每个安装生成一个随机 UUID device，持久保存在本地 `cinema/nas-sync-v1.json`。云端文件名为 `<device>-<12位十进制sequence>.json`。sequence 从1递增，先持久化待上传的完整文本，再提交不可变新文件。上传完成需逐字节回读；若响应丢失，重试同一文件必须与原文本一致。

读取目录后，每个 device 只取最高 sequence 的文件；读取或校验失败时保留本地资料并显示待同步，不以空数据覆盖。每个文件是已知寄存器的完整集合，包含从其他设备合并的版本，因此只需最新版本。成功上传并回读后，仅清理本 device 超过最近10个版本的旧文件，不清理其他设备或任意用户文件。其他客户端若在清理时遇到旧版本消失，应重新列目录重试。

```json
{
  "format": "NAKU-Account-Sync",
  "version": 1,
  "account": "<64位账号摘要>",
  "entries": {
    "cf:<CinemaTitle.key>": {
      "clock": 1792000000000,
      "device": "<UUID>",
      "deleted": false,
      "value": {"说明": "完整 CinemaTitle.toJson()"}
    }
  }
}
```

条目键：`cf:` 电影/剧集/NAS收藏；`ch:` 影院历史；`af:` 动漫收藏（后缀 Bangumi ID）；`ah:` 动漫历史（后缀 History.key）。影院历史值使用 `CinemaHistory.toJson()`；动漫历史使用 `HistorySyncCodec.historyToJson()`；动漫收藏值为 `{subject: HistorySyncCodec.bangumiItemToJson(...), time: epochMillis, type: 1..5}`。NAS 媒体 URL 使用已有 `https://nas.naku.invalid/media?...` 稳定引用，由各端登录后解析，不能写入临时登录直链。

## 合并、删除与并发

逐条比较 `(clock, device)`，clock 较大者胜，时间相同时按 device 字符串字典序确定唯一结果。新本地变更使用 `max(epochMillis, 已知最大clock+1)`。历史作为完整快照合并，不能把另一端的集数和本端的进度拼接。首次导入旧记录采用记录本身时间；没有原始收藏时间的影院收藏用1，防止新安装导入旧收藏后覆盖已知删除标记。

删除保留 `{clock, device, deleted:true}`，不可因记录不存在而丢弃标记。重新收藏产生更新的非删除版本。远端应用前再次比较当前本地值与请求前观察值；播放进度或收藏若已在本地变化，则保留新编辑并在后续同步生成新版本。

本地同步状态和待上传文本通过临时文件+原子改名落盘，上传失败保持原 sequence/text，防止重试覆盖不同内容。注销或切换账号会中止后续同步步骤；原生传输在异步操作后校验会话代次，避免使用新账号会话继续旧操作。

## 当前边界

单文件最大8MB，单账号最多100个写入设备，目录分页有上限；超过上限明确报错，不截断后上传空库。影院历史仍遵循原有最多200条的本地产品限制。来源站点配置不属于同步范围；另一端播放在线来源时仍需具有可用来源。此版本为最终一致性同步，不提供服务器事务或实时推送。新设备时钟应保持系统自动校时。
