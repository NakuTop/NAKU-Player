# 2.0.3 播放恢复与弹幕面板修复

## 隐藏恢复后不能播放

2.0.2 将 `NSWindow.isVisible == false` 也当成隐藏。启动、全屏及 Spaces 切换会暂时移出窗口，而应用并未隐藏；与此同时，显示通知按原生缓存去重，可能未把 `false` 再通知 Flutter。因此播放器会保留旧的隐藏标记，开启「隐藏时自动暂停」时拒绝播放。

2.0.3 根据 `NSApplication.isHidden` 判断，明确显示、应用激活和窗口成为主窗口时重新通知当前状态；手动播放及应用恢复前重新查询原生状态。查询期间到达的新隐藏事件优先，旧查询不能重新放行隐藏中的播放。显示只解除阻止，不自动播放；保持原播放器和播放进度。

另外，早于弹幕画布创建的暂停、恢复与清空改为安全操作；创建画布后应用之前记录的暂停状态。

## 关闭弹幕设置闪退

2.0.2 的本机崩溃堆栈位于 `FlutterMacOS` 的 `AccessibilityBridge::CreateRemoveReparentedNodesUpdate()` / `ui::AXNode::id()`，属于原生辅助功能树的空指针异常。设置中的 Material Slider 自带 `OverlayPortal`，在模态路由的增量更新中生成了没有父节点的语义节点，与 [Flutter 上游问题 #190357](https://github.com/flutter/flutter/issues/190357) 的节点异常一致。

设置滑杆及弹幕时间校准使用 `Overlay.wrap(alwaysSizeToContent: true)`，让滑杆浮层留在自身子树中。保留屏幕阅读器的 slider、increase / decrease 动作、键盘与拖动，不关闭全局辅助功能，不因关闭面板而暂停播放器。

## 验证范围

- 原生窗口回归程序：修复前已显示的窗口仍保留旧隐藏缓存，修复后首次显示即可清除。另验证热键注册、冲突、释放、按下 / 释放和长按防重复。
- 播放控件测试：首次空格及播放按钮修复漏发的恢复通知，保持同一个播放器；真正隐藏时继续阻止播放，过期查询不能覆盖新隐藏事件。
- 弹幕面板测试记录每一批实际发往引擎的语义节点。修复前连续三次打开产生 12 个孤立节点；修复后开关、拖动及时间校准没有孤立节点，且可调节的屏幕阅读器动作仍在。
- 独立的 macOS 发行沙盒测试程序启用真实原生辅助功能桥，在 1280×720 本地 H.264 视频播放期间连续开关弹幕设置 10 次并修改滑杆：程序正常完成，播放进度从 166 ms 前进至 10125 ms，关闭面板未暂停视频。
- 完整测试 885 项通过、19 项按既有条件跳过；分析 0 错误、0 警告、13 条既有 info。

独立测试不读取已安装播放器的片库、不替换应用程序。更新后的实际第三方片源、一起看和用户安装过程仍需在使用中确认。
